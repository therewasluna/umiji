نصب

اسکریپت نصب با خطا متوقف شد #

کادری را که نشان می‌دهد بخوانید: What happened خط‌های آخر مرحله‌ی شکست‌خورده را دارد و How to fix it می‌گوید چه کنید. گزارش کامل در /var/log/umiji-install.log است.

مشکل را درست کنید و بعد umiji را بنویسید، یا اسکریپت نصب را دوباره اجرا کنید. کارهایی را که انجام داده نگه می‌دارد.

می‌گوید root لازم است #

root شوید و همان دستور را دوباره اجرا کنید:

sudo -i

به GitHub یا ghcr.io نمی‌رسد #

فایل‌های نصب از GitHub و ایمیج‌ها از ghcr.io می‌آیند. بررسی کنید سرور می‌تواند بازشان کند:

curl -I https://ghcr.io

اگر جوابی نیامد، معمولاً DNS یا فایروال سرور جلویش را گرفته است. اگر شبکه‌ی سرور GitHub را مسدود می‌کند، بخش Troubleshooting در DEPLOY.md (به انگلیسی) نشان می‌دهد چطور ایمیج‌ها را از یک دستگاه دیگر بیاورید.

پورت‌های 80 و 443 اشغال‌اند #

یک وب‌سرور دیگر، معمولاً nginx یا Apache، آن‌ها را گرفته است. ببینید کدام است:

ss -ltnp

اگر لازمش ندارید متوقفش کنید و اسکریپت نصب را دوباره اجرا کنید. برای nginx:

systemctl disable --now nginx

اگر سرور سایت‌های دیگری هم دارد، نگهش دارید و در اسکریپت نصب My own nginx را انتخاب کنید: nginx خودتان، یا CDN را ببینید.

دیسک پر است #

ایمیج‌های Umiji حدود 2 گیگابایت جا می‌خواهند. ببینید چه چیزی جا را گرفته و ایمیج‌های قدیمی را پاک کنید:

df -h
docker image prune -a

دامنه و HTTPS

پنل باز نمی‌شود، یا مرورگر درباره‌ی گواهی هشدار می‌دهد #

گواهی HTTPS هنوز گرفته نشده است. این‌ها را به ترتیب بررسی کنید:

  1. دامنه به سرور اشاره می‌کند. روی کامپیوتر خودتان، nslookup panel.example.com باید IP سرور را نشان دهد. اگر نه، رکورد A آن را درست کنید.
  2. پورت‌های 80 و 443 در فایروال ارائه‌دهنده‌ی سرورتان، اگر دارد، باز هستند.
  3. در Cloudflare ابر خاکستری است، یا Always Use HTTPS خاموش است.

Caddy خودش دوباره تلاش می‌کند. گرفتن گواهی را این‌طور دنبال کنید:

cd /opt/umiji && docker compose logs -f umiji-caddy

پنل خطای 502 Bad Gateway می‌دهد #

پنل هنوز در حال بالا آمدن است، که حدود 30 ثانیه طول می‌کشد، یا متوقف شده است. وضعیت و گزارشش را ببینید:

cd /opt/umiji && docker compose ps
docker compose logs --tail 50 umiji

دامنه‌ی صفحه‌ی اشتراک چیزی نشان نمی‌دهد #

این طبیعی است. صفحه‌ی اشتراک فقط به لینک اشتراک یک کاربر جواب می‌دهد، نه به آدرس خالی‌اش. برای امتحان، یک لینک واقعی را از کارت یک کاربر باز کنید.

اگر آنجا خطای 502 می‌بینید، صفحه‌ی اشتراک روی این سرور اجرا نمی‌شود. umiji را بنویسید، Install / update را انتخاب کنید و تیک Sub page را بزنید.

لینک‌های اشتراک دامنه‌ی اشتباه دارند #

SUB_DOMAIN را در /opt/umiji/.env درست کنید و بعد پنل را دوباره راه بیندازید:

cd /opt/umiji && docker compose up -d

همه‌ی ورودها و سابقه‌های IP یک IP را نشان می‌دهند #

یک CDN، مثلاً ابر نارنجی Cloudflare، جلوی پنل است و پنل از آن خبر ندارد. رنج‌های IP آن CDN را معرفی کنید، مثل بخش nginx خودتان، یا CDN. برای نودها لیمیت IP پشت CDN را ببینید.

ورود

رمز مدیر را فراموش کرده‌ام #

روی سرور پنل umiji را بنویسید و Owner password را انتخاب کنید. یک رمز تازه می‌گذارد و ورود با رمز عبور را هم، اگر خاموش بوده، دوباره روشن می‌کند.

umiji

پیام Too many sign-in attempts #

بعد از 10 تلاش اشتباه برای یک نام کاربری، یا 20 تلاش از یک IP، پنل صبر می‌کند. 5 دقیقه بعد دوباره امتحان کنید.

نودها

نود آفلاین می‌ماند #

پنل به پورت نود نمی‌رسد، که 2222 است مگر اینکه عوضش کرده باشید. روی سرور نود، به IP پنل اجازه‌ی ورود بدهید، و پورت را در فایروال ارائه‌دهنده‌ی سرورتان هم باز کنید:

ufw allow from 203.0.113.10 to any port 2222 proto tcp

هنوز قرمز است؟ بررسی کنید نود اجرا می‌شود و گزارشش را بخوانید:

docker logs --tail 50 umiji-node

اگر گزارش درباره‌ی SECRET_KEY حرف می‌زند، کلید موقع کپی ناقص شده است. آن را دوباره از راه‌اندازی دستی کپی کنید و اسکریپت نصب را با node در انتهایش اجرا کنید.

نود کنار پنل آفلاین است #

نودی که اسکریپت نصب با نام Panel server اضافه کرده، از راه شبکه‌ی Docker روی همان سرور در دسترس است. اگر بعد از نصب فایروال را روشن کرده‌اید، به آدرس‌های Docker اجازه‌ی ورود بدهید:

ufw allow from 172.16.0.0/12 to any port 2222 proto tcp

نصب خودکار شکست می‌خورد #

اگر سر SSH متوقف می‌شود، IP، پورت SSH و رمز root را بررسی کنید. بعضی ارائه‌دهنده‌ها ورود root با رمز را خاموش می‌کنند؛ در این صورت از راه‌اندازی دستی استفاده کنید.

اگر سر ارتباط با پنل متوقف می‌شود، نود اجرا شده ولی پنل به آن نمی‌رسد: نود آفلاین می‌ماند را ببینید.

کاربرها و برنامه‌ها

برنامه وصل نمی‌شود #

مسیر را از سرور تا گوشی دنبال کنید:

  1. نود در صفحه‌ی نودها نقطه‌ی سبز دارد.
  2. نود اینباند را اجرا می‌کند: در پیکربندی هسته نود تیک خورده است.
  3. پورت اینباند، مثلاً 2083، در فایروال نود و فایروال ارائه‌دهنده‌ی سرورتان باز است.
  4. آدرس هاست IP عمومی سرور نود (برای Panel server همان IP سرور پنل، نه 172.x) یا دامنه‌ای است که به آن اشاره می‌کند، و پورت آن همان پورت اینباند است.
  5. برای REALITY، فیلد Target یک سایت HTTPS واقعی است که نود به آن دسترسی دارد.
  6. کاربر فعال است، نه محدود یا منقضی.

بعد از هر تغییر، اشتراک را در برنامه به‌روز کنید.

برنامه سروری نشان نمی‌دهد #

کاربر فقط وقتی یک هاست را می‌گیرد که قابلیت دیده شدن هاست روشن باشد و اینباند آن در یکی از اسکوادهای داخلی کاربر باشد. هر دو را بررسی کنید و بعد اشتراک را در برنامه به‌روز کنید.

لینک یک کاربر دست کس دیگری افتاده است #

کاربر را باز کنید، بعد عملیات بیشتر و لغو اشتراک را بزنید. لینک قبلی از کار می‌افتد و کاربر لینک تازه‌ای می‌گیرد که می‌توانید برایش بفرستید.

نگهداری

چطور به‌روزرسانی کنم؟ #

روی هر سرور umiji را بنویسید و Update all را انتخاب کنید. اول از دیتابیس پنل بکاپ می‌گیرد.

بردن پنل به یک سرور تازه #

  1. روی سرور قبلی umiji را بنویسید و Back up را انتخاب کنید.
  2. Umiji را روی سرور تازه نصب کنید و دامنه‌ها را به آن وصل کنید.
  3. فایل بکاپ را آنجا در /opt/umiji/backups/ بگذارید، umiji را بنویسید و Restore را انتخاب کنید.

ربات‌های تلگرام جواب نمی‌دهند #

ممکن است تلگرام روی سرور پنل مسدود باشد. یک پراکسی را به‌عنوان TELEGRAM_BOT_PROXY در /opt/umiji/.env بگذارید، مثل socks5://172.17.0.1:1080، و بعد پنل را دوباره راه بیندازید:

cd /opt/umiji && docker compose up -d

چیزی پیدا نشد. یک کلمه‌ی کوتاه‌تر امتحان کنید، یا در GitHub بپرسید.
